# Git 集成审计要求文档

> 粒度：L5 ｜ 版本：1.0 ｜ 日期：2026-08-07

## 1. 审计目标

验证 Git 集成功能满足需求文档的全部业务规则，且不破坏现有平台行为。所有验证使用**真实数据库种子数据**，禁止 Mock。

## 2. 验收标准

### 2.1 功能验收

| # | 验收点 | 通过标准 | 验证方式 |
|---|--------|---------|---------|
| F1 | 凭证配置 | 设置 → Git 集成：可分别保存/清除 GitHub、Gitee Token；保存后显示"已配置"，明文不泄露 | 前端操作 + `GET /api/git/config` 断言 |
| F2 | 凭证隔离 | 用户 A 配置 Token，用户 B 的 `GET /api/git/config` 显示未配置 | 双账号 API 断言 |
| F3 | 文件夹-仓库绑定 | `PUT /api/folders/{id}/git` 保存 provider/repo_url；非法 provider/非 https 被拒 | API 断言 |
| F4 | 首次拉取选文件夹 | 未绑定文件夹会话点「拉取」弹出选择器，选中后拉取成功 | 浏览器实测 |
| F5 | 后续拉取默认 | 已绑定文件夹会话点「拉取」直接拉取到绑定文件夹，不弹选择 | 浏览器实测 |
| F6 | 拉取落库 | 拉取后文件夹文件列表出现远端文件，内容与仓库一致 | API + 浏览器 |
| F7 | 推送整文件夹 | 文件夹新增/修改文件后推送，远端仓库出现对应变更 | 浏览器 + 远端仓库验证 |
| F8 | 过程显示 | 拉取/推送过程日志实时出现在会话显示区，结束时显示成功/失败摘要 | 浏览器实测 |
| F9 | 未配置 Token 提示 | 未配 Token 时拉取/推送返回 400 明确错误，前端提示去设置 | API + 浏览器 |

### 2.2 安全验收

| # | 验收点 | 通过标准 |
|---|--------|---------|
| S1 | Token 不出网 | 所有 GET 响应不含明文 Token；SSE 日志不含 Token |
| S2 | 命令注入防护 | repo_url 含恶意字符（`;`、`$(...)`、`|`）时按普通文本处理，不产生 shell 执行；用参数列表方式执行 |
| S3 | 用户边界 | 无接口可读写其他用户 Token / 其他用户文件夹 git 字段 |
| S4 | 失败不破坏数据 | 推送认证失败时文件夹 DB 文件不被删除/回写；git_updated_at 不更新 |

### 2.3 回归验收

| # | 验收点 | 通过标准 |
|---|--------|---------|
| R1 | 工作空间绑定不回归 | 原有"绑定文件夹→写文档→自动归档"流程仍正常 |
| R2 | 迁移可回滚 | `0016_git_folder_fields` downgrade 正常 |
| R3 | typecheck / 后端启动 | 前端 `tsc --noEmit` 零错误；网关可启动，`GET /api/git/config` 200 |

## 3. 测试用例

### 3.1 后端（API 级，Python 脚本断言）

1. **TC-CONFIG-1**：登录 → `GET /api/git/config` 全未配置 → `PUT` 保存 github_token → 断言 `configured=true`、响应不含 token 明文 → `PUT` 空串清除 → 断言 `configured=false`。
2. **TC-CONFIG-2**：用户 B 登录 → `GET /api/git/config` 仍全未配置（隔离）。
3. **TC-BIND-1**：`PUT /api/folders/{id}/git {provider:"gitee", repo_url:"https://gitee.com/owner/repo.git"}` → `GET` 回读一致。
4. **TC-BIND-2**：`provider:"gitlab"` → 422；`repo_url:"ftp://..."` → 422。
5. **TC-PULL-1**：未绑定仓库文件夹 `POST /api/git/pull` → 400。
6. **TC-PULL-2**：绑定 github 仓库 + 已配 token → SSE 收到 `done: {ok:true}`，文件夹文件数 > 0。
7. **TC-PUSH-1**：文件夹新增文件 → `POST /api/git/push` → `done: {ok:true}`；远端仓库存在该文件。
8. **TC-PUSH-2**：不配 token → `done:{ok:false}` 或 400，且文件夹文件未被破坏。

### 3.2 前端（浏览器实测）

1. **TC-UI-1**：设置 → Git 集成 → 输入 Token 保存 → 显示已配置、无明文回显。
2. **TC-UI-2**：新建会话（未绑定）点「拉取」→ 弹选择器 → 选「我的工作空间/默认文件夹」→ 日志流显示 → 完成后文件列表出现远端文件。
3. **TC-UI-3**：已绑定会话点「拉取」→ 直接拉取，不弹选择。
4. **TC-UI-4**：修改文件夹文件后点「推送」→ 日志流 → 成功摘要；远端验证变更。
5. **TC-UI-5**：未配 Token 时推送 → 明确错误提示。
