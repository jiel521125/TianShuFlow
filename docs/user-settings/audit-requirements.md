# 用户级设置（User Settings）审计要求文档

> 粒度：L5 ｜ 版本：1.0 ｜ 日期：2026-08-06

## 1. 审计目标

对「用户级设置」功能实施两层审计：**功能审计**（业务正确性、隔离性、回归）与 **安全审计**（调用 TRAE-security-review Skill 执行）。

## 2. 功能审计清单

### 2.1 数据隔离
- [ ] 用户 A 的设置对用户 B 完全不可见（按 `user_id` 精确过滤，SQL 层 where 条件必须含 user_id）。
- [ ] 无认证开发模式下统一回退 `default` 用户，且不会泄露其他用户行。

### 2.2 合并与默认值
- [ ] `effective = deep_merge(default, override)`；未修改区块 `value=null` 且 `effective==default`。
- [ ] 重置（DELETE）后恢复默认，前端显示恢复。
- [ ] 部分覆盖：PUT `{theme:dark}` 后 locale 仍为默认值。

### 2.3 校验
- [ ] 非法 theme/locale/布尔/数组类型 → 400 + 明确 detail，且不落库。
- [ ] 未知 section → 404。
- [ ] 空 body / 非对象 body → 400。

### 2.4 前端行为
- [ ] 外观、通知页首次进入显示后端生效值（非 localStorage 残留）。
- [ ] 修改后刷新/新标签页保持（写库生效）。
- [ ] 工具/渠道/集成页「个性化偏好」区默认继承全局；关闭继承后勾选列表生效并持久化。
- [ ] 重置按钮可用且即时生效。
- [ ] 全程真实数据（无 Mock）。

### 2.5 迁移
- [ ] `0013_user_settings` 在 PostgreSQL 执行成功；重复执行幂等。
- [ ] SQLite 兼容。

### 2.6 回归
- [ ] 用户模型（Models）、记忆、技能功能不受影响。
- [ ] 前端 `pnpm typecheck` 零新增错误。

## 3. 安全审计清单（TRAE-security-review）

- [ ] 端点不泄露其他用户的设置（越权读取/写入）。
- [ ] 输入校验无绕过（类型混淆、原型污染、超长字符串）。
- [ ] SQL 注入（ORM 参数化，无字符串拼接）。
- [ ] 不记录敏感字段（本需求不涉及密钥；确认路由日志不打印 value）。
- [ ] CSRF：写操作与现有 API 认证/授权机制一致。
- [ ] JSONB 写入大小限制（防 DoS）。
- [ ] 依赖与配置无硬编码密钥。

## 4. 审计执行方式

1. 后端：编写/执行针对上述清单的接口级验证（真实数据库）。
2. 前端：typecheck + 浏览器端到端。
3. 安全：调用 `TRAE-security-review` Skill 对变更 diff 审查，修复发现项后复测。
4. 结果记录：在本文件末尾追加审计结论（通过/失败 + 修复记录）。
